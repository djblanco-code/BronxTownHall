- Event sourcing: scraped events land only in `scraped_events` for admin review; approval is the sole path into `bronx_resources` (keeps human verification as the publish gate).
- Ask a Question: the AI only extracts search terms and picks IDs from listings retrieved from our own data; every displayed detail is rendered from the listing record, never AI text (prevents invented answers).
- Structure: workflows live in `src/features/<name>/` and are imported only through that folder's `index.ts`; route files stay thin. Bottom-fixed UI uses the `app-float-bottom` / `app-dock-bottom` utilities, and a page's floating button goes through `<AppShell fab>`. See `docs/mobile-first-refactor.md` for the piece-by-piece plan.
- Design: every page follows `docs/design-system.md` (friendly and photo-led: real Bronx photos with credits, soft corners, hairline lists, no shadows on content, Lucide icons never emoji, Bricolage + Atkinson type, Bronx flag colors on white). Home is the reference.
- Hosting: Vercel + the team's own Supabase project, no Lovable services. Env vars and setup live in `docs/self-hosting.md`; keep `.env.example` in sync when adding one. Schema changes are new files in `supabase/migrations` (applied with `npx supabase db push`).
- Pull requests: one change per PR, titled `type: lowercase verb phrase emoji` (feat, fix, refactor, docs, test, chore), using `.github/pull_request_template.md`, squash-merged once CI and the Vercel preview pass. Details in `CONTRIBUTING.md`.
- Product scope: `docs/product-scope.md` says what the first version includes and leaves out; check features against it. Two helper agents live in `.claude/agents/`: `product-manager` (scopes a request into a one-PR brief) and `senior-auditor` (security, privacy and bug review before merging).
