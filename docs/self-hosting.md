# Hosting The Bronx App yourself (Vercel + Supabase)

The app no longer depends on Lovable. You need:

- a **Vercel** project connected to this GitHub repo (hosting),
- a **Supabase** project (database, sign-in, file storage),
- optionally: an **OpenAI** key (Ask a question, smart search, natural voice),
  a **Google Maps** key (map and address checks), and a **Firecrawl** key
  (weekly event scraping). Everything else works without them.

Steps 1–4 are a one-time setup. Allow about 30 minutes.

## 1. Create the Supabase project

1. Sign up at [supabase.com](https://supabase.com) and create a new project.
   Pick the **East US** region (closest to the Bronx) and save the database
   password somewhere safe.
2. From the project's dashboard, note:
   - **Project URL**: `https://<project-ref>.supabase.co`
   - **Publishable key** (shown as the `anon` key on older projects): safe to expose
   - **Secret key** (`service_role` on older projects): **server only, never share it**

## 2. Create the tables

All 64 migrations live in `supabase/migrations` and apply in filename order.
From your computer, in a clone of this repo:

```bash
npx supabase login
```

```bash
npx supabase link --project-ref <project-ref>
```

```bash
npx supabase db push
```

`db push` asks for the database password from step 1. When it finishes you
have every table, security policy and function the app expects.

## 3. Set up sign-in

In Supabase, under **Authentication → URL Configuration**:

- **Site URL**: your Vercel address, e.g. `https://bronxtownhall.vercel.app`
- **Redirect URLs**: add `https://bronxtownhall.vercel.app/**` and
  `http://localhost:8080/**` (for local development)

Email + password sign-in works with no further setup.

**Google sign-in** (optional): create an OAuth client in Google Cloud
(APIs & Services → Credentials → OAuth client ID → Web application) with
the authorized redirect URI `https://<project-ref>.supabase.co/auth/v1/callback`,
then paste its client ID and secret into **Authentication → Providers → Google**.

## 4. Add the environment variables in Vercel

Vercel → your project → **Settings → Environment Variables**. Add each one
for Production (and Preview if you use preview deploys), then **redeploy**.
`VITE_*` values are baked in when the site builds, so a change only takes
effect after a new deployment.

| Variable | Required | What it is |
|---|---|---|
| `VITE_SUPABASE_URL` | Yes | Supabase Project URL |
| `VITE_SUPABASE_PUBLISHABLE_KEY` | Yes | Supabase publishable (`anon`) key |
| `SUPABASE_SERVICE_ROLE_KEY` | Yes | Supabase secret (`service_role`) key. Server only: never give it a `VITE_` prefix |
| `VITE_SITE_URL` | If you use a custom domain | e.g. `https://bronxtownhall.org`. Defaults to your Vercel production domain |
| `OPENAI_API_KEY` | Optional | Turns on Ask a question, smart search and the natural voice. Without it, listening uses the browser's built-in voice |
| `AI_MODEL` | Optional | Chat model (default `gpt-4.1-mini`). Must support JSON-schema output |
| `AI_TTS_MODEL` | Optional | Voice model (default `gpt-4o-mini-tts`) |
| `OPENAI_BASE_URL` | Optional | Any OpenAI-compatible API instead of OpenAI |
| `VITE_GOOGLE_MAPS_BROWSER_KEY` | Optional | Shows the map. Restrict it to your domain in Google Cloud |
| `GOOGLE_MAPS_API_KEY` | Optional | Server-side address checks (Geocoding + Places APIs) |
| `FIRECRAWL_API_KEY` | Optional | Weekly event scraping into the admin review queue |
| `VITE_SMS_NUMBER` | Optional | The "Text FOOD to…" number, once the text line exists |

Vercel detects the build on its own (`npm run build`, Node 22). Nothing else
needs configuring.

## 5. Make yourself an admin

Sign up on your live site, then in Supabase → **SQL Editor** run (with your email):

```sql
insert into public.user_roles (user_id, role)
select id, 'admin' from auth.users where email = 'you@example.com'
on conflict do nothing;
```

Reload the site; `/admin` now opens.

## 6. Scheduled jobs (optional)

Two weekly jobs run from the database. Replace `YOUR-DOMAIN` and run in the
SQL Editor once the site is live.

Re-check listings (needs `GOOGLE_MAPS_API_KEY`):

```sql
select cron.schedule('weekly-resource-verification', '0 7 * * 1', $$
  select net.http_post(
    url := 'https://YOUR-DOMAIN/api/public/verify-resources',
    headers := '{"Content-Type": "application/json"}'::jsonb,
    body := '{"batch_size": 10}'::jsonb
  );
$$);
```

Find new events for admin review (needs `FIRECRAWL_API_KEY`). The shared
secret was generated by the migrations and never leaves the database:

```sql
select cron.schedule('weekly-event-scrape', '0 8 * * 1', $$
  select net.http_post(
    url := 'https://YOUR-DOMAIN/api/public/hooks/scrape-events',
    headers := jsonb_build_object(
      'Content-Type', 'application/json',
      'x-cron-secret', (select value from public.internal_settings where key = 'event_scrape_cron_secret')
    )
  );
$$);
```

## 7. Bring over data from Lovable Cloud

The built-in listings in `src/lib/data.ts` come with the code. Rows that live
only in the old Lovable database do not: imported directory listings
(`bronx_resources`), approved events, submissions, and accounts.

- **Tables**: export each table you need as CSV from Lovable's Cloud database
  view (or ask Lovable support for a database export), then import it in
  Supabase → **Table Editor → Import data from CSV**. Import parent tables
  before the tables that point at them (e.g. `bronx_resources` before
  `bronx_resource_sources`).
- **Accounts** cannot be moved with their passwords. People sign up again
  (or use Google sign-in); then repeat step 5 for admins.

## Local development

Copy `.env.example` to `.env`, fill in at least the three required values, then:

```bash
npm install
```

```bash
npm run dev
```

The app runs at http://localhost:8080. `npm run build` then `npm start` runs
the production server locally.
